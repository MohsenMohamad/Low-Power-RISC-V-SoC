# Cross-branch SoC interface audit

Repository: `MohsenMohamad/Low-Power-RISC-V-SoC`. Snapshot: 5 November 2026. Source files were not modified, branches were not merged, and no fixes were made.

This report lists concrete incompatible interface contracts and divergent assumptions in the five implementation branches. References identify the branch through the key below and link to the audited commit, not to a moving branch head. `F/D` means the relevant file is byte-identical in the firmware and debug heads; the link goes to F unless marked D. D has already merged F; those two are not independent implementations of their shared files.

Severity meanings:

- **Blocks integration:** the supplied components do not provide a coherent directly connectable, buildable, bootable, or verifiable combined SoC at that boundary.
- **Causes wrong behavior:** a connection or build can be made, but the unchanged assumptions produce wrong data, sequencing, interrupts, test results, or reports. These include defects exposed after the preceding integration blockers are resolved.
- **Cosmetic:** differing metadata/documentation with no functional effect in the supplied consumers.

This is a source/interface audit. It includes branch/file comparisons, read-only execution of the existing regression-discovery function, and probes of the existing log/coverage parsers. All 378 extracted source-file instances matched their Git blob hashes after the audit. HDL simulation, firmware compilation, and formal proofs were not rerun: Verilator, Icarus, Yosys, SymbiYosys, and RISC-V GCC were not installed in the audit environment. Existing branch result claims are not presented as fresh validation. Consequences described below are deductions from the cited producer and consumer code.

**Findings:** 58 total: 20 blocks integration, 36 causes wrong behavior, 2 cosmetic. A finding may include an exact register/port comparison table; its individual rows are not counted as separate findings.

## Blocks integration

### B01 — Global address map and linked RAM addresses

**SPEC:** Partial. It fixes ROM at 16 KB and retained RAM at 128 KB, but assigns no base addresses or peripheral apertures ([M · doc/SPEC.md:8](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/964f9dcd04d06eea324de777a714c3b9bef63b0d/doc/SPEC.md#L8)).

| Region/interface | C | S | F/D and host tools |
|---|---|---|---|
| Boot ROM | `0x00000000`, 16 KB cache window | `0x00000000`, 16 KB | `0x00000000`, 16 KB |
| Main RAM | `0x80000000`, 128 KB cache window | `0x10000000`, 128 KB | `0x20000000`, 128 KB |
| Application | Unit-test ELF at `0x80000000`, 4 MB test memory | ROM-resident program; data/stack at `0x10000000` | Image/header at `0x20001000`; stack top `0x20020000` |
| UART | No production peripheral map | `0x20000000`, 4 KB | `0x40000000`, 4 KB |
| Machine timer | Testbench-only synthetic devices | `0x20001000`, 4 KB | `0x40010000`, 64 KB CLINT aperture |
| INTC | No production peripheral map | `0x20002000`, 4 KB | `0x40001000`, 4 KB |
| PMU | No production peripheral map | `0x20003000`, 4 KB | `0x40002000`, 4 KB; U's subsystem map defaults to base 0 |
| Wake timer | None | `0x20004000`, 4 KB | Combined with machine timer; no separate peripheral |

### B02 — Uncached RAM alias is required by firmware but absent in S

**SPEC:** Silent on aliases and address-based cacheability ([M · doc/SPEC.md:6](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/964f9dcd04d06eea324de777a714c3b9bef63b0d/doc/SPEC.md#L6)).

- S decodes exactly one RAM window at `0x10000000`; neither `0x30000000` nor a second alias exists: [S · rtl/aon/aon_subsys.sv:71](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/97cffe219e880de4f772be06fce451893a7ee26c/rtl/aon/aon_subsys.sv#L71).
- F suite state and D mailbox use the alias, rather than optional test-only access: [F · fw/app/suite.c:35](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/eca08efaf5bca90757140f96568afe959043c869/fw/app/suite.c#L35), [D · fw/debug/app/dbg_app.c:29](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/bd9ca101488be5fced2bd151c3596f053d1bb01d/fw/debug/app/dbg_app.c#L29), [D · fw/debug/include/dbg_mbox.h:13](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/bd9ca101488be5fced2bd151c3596f053d1bb01d/fw/debug/include/dbg_mbox.h#L13).

**Effect:** retained suite state, reboot bookkeeping, debug run control, and coherence tests access an unmapped region. Merely moving F's RAM base to S's would make its fixed alias offset land on S's UART.

### B04 — UART register map is incompatible even after rebasing

**SPEC:** Names UART but defines no registers, FIFO size, or interrupt bits ([M · doc/SPEC.md:10](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/964f9dcd04d06eea324de777a714c3b9bef63b0d/doc/SPEC.md#L10)).

| Offset | S RTL and its firmware | F/D RTL, driver, monitor |
|---|---|---|
| `00` | TX push; read returns TX-full in bit 31 | TX push / RX pop; read returns RX byte |
| `04` | RX pop; bit 31 = empty | STATUS: full/idle/RX/overrun bits 0..3 |
| `08` | STATUS bits 0..3, overrun W1C | IE bits 0..1 |
| `0C` | DIV in 15:0 **plus** RX/TX IRQ enables in bits 16/17 | DIV only; interrupt enables are separate |

| DIV limits | RTL stores all 16 bits; its register-map document requires DIV >= 2 | RTL clamps values below 4 to 4 |

**Branch evidence:** S actual definitions/decode [S · rtl/aon/aon_uart.sv:2](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/97cffe219e880de4f772be06fce451893a7ee26c/rtl/aon/aon_uart.sv#L2), [S · rtl/aon/aon_uart.sv:128](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/97cffe219e880de4f772be06fce451893a7ee26c/rtl/aon/aon_uart.sv#L128), divider convention [S · doc/SOC_REGMAP.md:68](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/97cffe219e880de4f772be06fce451893a7ee26c/doc/SOC_REGMAP.md#L68), S firmware [S · fw/include/soc.h:13](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/97cffe219e880de4f772be06fce451893a7ee26c/fw/include/soc.h#L13); F/D actual definitions/decode [F · platform/picorv32/rtl/aon_uart.sv:1](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/eca08efaf5bca90757140f96568afe959043c869/platform/picorv32/rtl/aon_uart.sv#L1), [F · platform/picorv32/rtl/aon_uart.sv:66](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/eca08efaf5bca90757140f96568afe959043c869/platform/picorv32/rtl/aon_uart.sv#L66), driver [F · fw/drivers/uart.c:6](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/eca08efaf5bca90757140f96568afe959043c869/fw/drivers/uart.c#L6), symbolic map [F · fw/app/monitor.c:27](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/eca08efaf5bca90757140f96568afe959043c869/fw/app/monitor.c#L27).

### B07 — Cache maintenance uses a CSR in C, memory-mapped registers in F/D

### B08 — Boot/resume context, image header, and persistent-memory ABI

**SPEC:** Requires cold/resume detection and architectural restore, but gives no handoff address, context format, magic, CRC, or image format ([M · doc/SPEC.md:20](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/964f9dcd04d06eea324de777a714c3b9bef63b0d/doc/SPEC.md#L20), [M · doc/SPEC.md:46](https://github.com/MohsenMohamad/Low-Power-RISC-V-SoC/blob/964f9dcd04d06eea324de777a714c3b9bef63b0d/doc/SPEC.md#L46)).

| Contract | S firmware/ROM | F/D firmware/ROM/tools |
|---|---|---|
| Resume detection | PMU.STATUS.RESUME bit 16 + SCRATCH1 `0x5E5E0A0A` | PMU.RST_CAUSE `2` or `3` + saved context validity |
| Context location | Pointer in SCRATCH0 to linker-allocated `pm_ctx` | Fixed `RAM_BASE+0x40`, within handoff at RAM base |

| Reserved RAM | Linker allocates data/BSS from RAM base; stack at top | handoff `+000`, persistent `+200..3FF`, ROM work/stack `+400..FFF`, app `+1000` |
